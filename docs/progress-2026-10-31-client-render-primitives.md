# Renderer portability and owned raw-image commands

This checkpoint combines bounded renderer portability and resource milestones, without initializing a complete game renderer or CL_Frame. The independent shared-header change in b850cdac separates real D3D surface release from shared header compilation. Linux has no fake successful GPU release implementation: actual release remains unavailable at link time. Radiant-only Material alignment matches the documented Windows layout while MP layout stays unchanged. See the separate portability checkpoint and compiler evidence for the actual legacy render-command translation unit.

RC_STRETCH_RAW and GfxCmdStretchRaw already existed in the engine backend, where RGBA input is uploaded to an X8R8G8B8 surface. This change adds a producer for that existing format (R_EmitStretchRawCommand and game R_AddCmdStretchRaw); it does not claim a previous producer was already present. The Linux CPU renderer supports only clipped 1:1 blits. Scaling rejects explicitly rather than silently substituting for D3D linear filtering. Source alpha is ignored and output is opaque, matching the X8 surface semantics.

Upload validates and copies padded rows into immutable owned storage, returning a monotonically increasing handle. Upload/release require ready state; recording and pending presentation prohibit resource mutation. Images survive surface resize. Shutdown releases them without reusing handle generations on restart. Explicit budgets allow at most 64 resources and 256 MiB of uploaded pixels, in addition to dimension bounds. Failed image or map-node allocation preserves existing resources.

A raw command pointer does not authorize reading memory. Internal recording supplies a command-offset/handle sidecar; submission validates its generation, live pointer and exact dimensions. Public externally supplied lists reject every raw command, including pointers matching reused allocations. Resize/cancel/shutdown invalidate command bindings. Caller upload memory can be modified or destroyed immediately after upload.

Submission snapshots bounded command bytes, validates the entire list, then replays clear/image commands in order without further allocation. A late unsupported command cannot partially execute. Snapshotting also prevents framebuffer-backed command bytes changing during replay. Widened signed destination arithmetic preserves clipping offsets and avoids extreme-coordinate overflow. No materials, world geometry, depth/stencil, GPU upload, blending or filtering is implied.
