# Linux client CPU presentation and frame pacing

This checkpoint extends the existing optional `KisakCOD-client-input` host with a reusable CPU pixel resource and synchronous SDL window presentation. It does not initialize the game's D3D9 renderer, audio, cgame, or `CL_Frame`. The default dedicated build remains independent of SDL.

`PixelBuffer` owns tightly packed RGBA bytes with checked dimensions, transactional resize, explicit move/reuse semantics, and no SDL lifetime dependency. A borrowed `PixelBufferView` additionally permits padded rows. `WindowHost::Present` validates the complete accessed row span and exact current surface dimensions, reacquires the SDL surface on every call, converts literal RGBA bytes to its native format, and completes the copy before returning. Resize invalidates old resource views; callers query the actual surface pixel extent rather than assuming logical event dimensions. Closed/wrong-thread access and SDL failures report errors.

The existing input executable now presents four diagnostic color quadrants using that resource. These are diagnostic pixels, not game rendering. Surface resizing reallocates only when its actual dimensions change. A steady-clock deadline gates the existing command tick, mouse sample consumption, and presentation at a 16 ms minimum interval while events continue to be pumped. A hitch schedules the next deadline from the current time, so missed periods do not cause catch-up bursts. This is host pacing, not engine simulation timing.

Build with the existing `KISAK_BUILD_LINUX_WINDOW_HOST=ON` option and a matching 32-bit SDL2 SDK; run `KisakCOD-client-input --frames 3 --trace` or `--run-ms 1000`. New focused targets are `KisakCOD-presentation-test`, `KisakCOD-pixel-resource-test`, and `KisakCOD-frame-deadline-test`. `scripts/tests/test_linux_window.py` builds and executes them. The SDK/runtime here are the previously documented official Debian SDL2 packages extracted under `/workspace/native-tools/sdl-root`, not installed system-wide or vendored into the repository.

Validation evidence is retained in `/workspace/kisakcod-client-presentation-results`. Real SDL surface tests check exact asymmetric colors, alpha-independent conversion, padded rows, synchronous copying, malformed views, actual resize, thread ownership, shutdown, and recreation. Pure resource ownership tests also run with native64 ASan/UBSan; deadline tests use deterministic clocks including 10,000 early event arrivals and long stalls. X11 tests use an isolated Xvfb server and XGetImage to read actual displayed pixel colors at three sizes. The prior solid-fill executable is a negative control and fails the pixel-color assertion. These prove SDL presentation and OS-window behavior, not physical GPU rendering or gameplay.
