# Native admitted menu traversal

The existing menu owner now calls the actual production `Menu_Paint -> Item_Paint` path instead of maintaining separate background and control drawing loops. One stable menu graph contains the genuine admitted items in source order: eight decorative items, followed by the four previously admitted labels/yes-no controls. Their parents, menu pointer array and input navigation refer to the same graph. The remaining source menu items are not claimed to run.

`Menu_IsVisible`, `Menu_Paint` and `Item_Paint` are extracted without changing their game bodies. Actual visibility, `ui_showMenuOnly`, `Menu_UpdatePosition`, text-cache invalidation, window painting and type dispatch execute. Decorative type0 items naturally produce no text when their genuine text/expression/dvar fields are empty. The normal game retains its existing implementations for all services.

The bounded CPU entry validates the entire graph, including hidden items, before any traversal. It checks the real menu-filter dvar type and bounded nonnull names before production pointer/string access. It admits owned materials/fonts, decorative/text/yes-no types, supported window/text styles and bounded literal expressions. It rejects general visibility/numeric expressions, owner-draw/cgame-dependent flags, sound callbacks, dynamic widgets, style5 material-from-dvar behavior and unsupported text/alignment before entering assertion-bearing production helpers. Link-selected services for excluded branches throw if reached; none report success.

The composition format is now KUCOMP02. It preserves actual type fields and the genuine literal material expression in stable owned storage. `Item_Paint` evaluates that expression through `GetExpressionResultString`, then calls the scoped owned `Material_RegisterHandle` resolver. Material names identify one owned resource, shared by repeated items. This resolver performs no filesystem/game material registration and deliberately does not implement `imageTrack` accounting; that field was not exported and is not represented as preserved. Unknown names or pointers fail.

The control window's real style1 null-background branch uses the shared actual fill-rectangle geometry with the admitted owned white material. It is not skipped merely because the current background tint is transparent. Font selection remains the actual selector with only owned role resources available.

A traversal snapshots command bookkeeping, all resource sidecar counts, menu/item state and the compositor accumulator. Exceptions restore that state and scoped globals. The owner additionally restores its graph after later submission/presentation failure, cancels pending commands and releases custom cursor visibility. As before, a display failure after CPU replay does not imply pixel rollback.

The genuine selected menu requests blur radius7. `Menu_Paint` performs its actual squared-radius accumulation. The owner resets the accumulator once per frame, matching the production `Menu_PaintAll` boundary, and consumes an explicit result: painted status, requested blur and unsupported-postprocess status. Successful presentations report `menu_traversal painted=... item_count=12 blur_requested=... blur_rendered=0 compositor=partial`. Metadata is not rewritten to zero and no blur effect is claimed. This remains a partial UI command submission, not a complete compositor or full frame.

Synthetic-resource tests execute the real traversal to verify overlap ordering, hidden items, parent movement, cache invalidation, literal material identity, per-frame and within-frame blur accumulation, menu-name filtering, whole-graph rejection and late command-capacity rollback. Genuine asset lifecycle/input and independent X11 readback remain separate evidence. No networking, authentication, gameplay or previously denied packet work is included.
