# Reproduction commands

This combined review branch already includes both series; do not apply their cumulative patches again. Commands below assume Bash and a host able to run ELF32. Paths are user-supplied, not paths from the original build machine. Builds and asset outputs should be outside any existing worktree used concurrently for other tasks.

## Client checks

```sh
export REPO=/absolute/path/to/review/KisakCOD
export TRACY_SOURCE=/absolute/path/to/existing/matching/tracy
export SDL2_CMAKE_DIR=/absolute/path/to/i386/SDL2/cmake/SDL2
export CC=clang-19 CXX=clang++-19 JOBS=3
export BUILD_ROOT=/absolute/path/to/new/build-overnight
bash /absolute/path/to/delivery/build-and-check.sh
```

The helper runs the checked-in `test_linux_window.py` and `test_linux_client_core.py` unchanged. The window checker builds all relevant targets, runs the explicitly selected SDL dummy driver and includes the actual traversal/parser/sampling fixtures. The core checker verifies default-OFF behavior and dedicated-output preservation. Inspect exit status and the final zero-failure summaries; do not assume the historical counts remain identical if additional commits are included.

With an SDL SDK unpacked outside system directories, supply its multiarch include and transitive link paths as well:

```sh
export SDL_SDK=/absolute/path/to/local/i386-sdk
export EXTRA_CXX_FLAGS="-m32 -I$SDL_SDK/usr/include/i386-linux-gnu"
export EXTRA_LINKER_FLAGS="-m32 -Wl,-rpath-link,$SDL_SDK/usr/lib/i386-linux-gnu -Wl,-rpath-link,$SDL_SDK/usr/lib/i386-linux-gnu/pulseaudio"
export LD_LIBRARY_PATH="$SDL_SDK/usr/lib/i386-linux-gnu:$SDL_SDK/usr/lib/i386-linux-gnu/pulseaudio${LD_LIBRARY_PATH:+:$LD_LIBRARY_PATH}"
```

Only use directories matching the compiler/runtime ABI. SDK layout is distribution-specific. Missing transitive PulseAudio symbols and missing SDL multiarch configuration headers were real setup failures in the original environment; the explicit paths above address those cases without changing source.

## Dedicated build and existing regressions

Keep the server output separate from optional client targets. Reuse the local-only dependency toolchain generated by the helper above:

```sh
cd "$REPO"
SERVER_BUILD="$BUILD_ROOT/server-Debug"
cmake -S . -B "$SERVER_BUILD" -G Ninja -DKISAK_PLATFORM=linux \
  -DCMAKE_BUILD_TYPE=Debug -DCMAKE_C_COMPILER="$CC" -DCMAKE_CXX_COMPILER="$CXX" \
  -DCMAKE_C_FLAGS=-m32 -DCMAKE_CXX_FLAGS=-m32 \
  -DCMAKE_TOOLCHAIN_FILE="$BUILD_ROOT/local-dependencies.cmake" \
  -DCMAKE_RUNTIME_OUTPUT_DIRECTORY="$SERVER_BUILD/bin"
cmake --build "$SERVER_BUILD" --target KisakCOD-dedi -j "$JOBS"
python3 scripts/tests/run_linux_checks.py --build-dir "$SERVER_BUILD" \
  --binary "$SERVER_BUILD/bin/KisakCOD-dedi" --cxx "$CXX" \
  --log-dir "$BUILD_ROOT/server-check-logs"
```

Repeat with a distinct build directory and `RelWithDebInfo` for the other configuration. The runner does not configure or build the dedicated executable itself. It exercises existing asset-free tests; some checks use local UDP fixtures. This handoff does not authorize new packet/auth development or tests beyond the existing suite.

The existing live bot fixture requires authorized local game assets and the server changes already included in this branch:

```sh
GAME_DIR=/absolute/path/to/authorized/CoD4
python3 scripts/tests/test_linux_bots.py "$GAME_DIR" \
  --binary "$SERVER_BUILD/bin/KisakCOD-dedi" --bots 3 \
  --refill-cycles 3 --cycles 2 --hold-seconds 5 --timeout 90 --keep
```

This launches an isolated test server and exercises real kick/drop, full-capacity reuse and retained-bot map transitions. It is not an authentication or two-human-player gameplay test. Read the fixture and choose the run environment deliberately; no external devices or production servers are required.

## When native ELF32 execution is unavailable

Original tests used an existing `qemu-i386` runner plus an existing i386 runtime/SDK. **Setting CMAKE_CROSSCOMPILING_EMULATOR alone does not make these Python checkers work:** they launch ELF32 test executables directly, including freshly compiled temporary fixtures. The original environment had a local Python subprocess execution adapter; that environment-specific adapter is not supplied here. Consequently, the full helper above is supported as written on a native ELF32-capable host, not advertised as a turnkey QEMU aggregate harness.

Individual fixtures can be run explicitly with QEMU and a matching sysroot:

```sh
QEMU=/absolute/path/to/qemu-i386
I386_SYSROOT=/absolute/path/to/complete/i386-root
"$QEMU" -L "$I386_SYSROOT" "$BUILD_ROOT/Debug/bin/KisakCOD-cpu-traversal-test"
```

The sysroot must contain the binary's requested dynamic linker and matching libraries. For a separate SDL SDK, QEMU_SET_ENV can set guest LD_LIBRARY_PATH; do not accidentally feed host tools incompatible i386 libraries. A project-provided execution adapter would need separate validation before claiming complete QEMU aggregate reproduction. Native 32-bit ASan was unavailable in the original environment and was not retried; native64 portable sanitizer checks are separate evidence.

## Optional real-window checks

On an X11-capable Linux host with Xvfb and xdotool:

```sh
cd "$REPO"
python3 scripts/tests/test_linux_window_x11.py \
  "$BUILD_ROOT/Debug/bin/KisakCOD-client-input" \
  --engine-input --relative --log-dir "$BUILD_ROOT/x11-input"
```

The script creates a private Xvfb server; it does not need weakened X11 authentication. For the genuine menu, once a compatible private bundle is available:

```sh
python3 scripts/tests/test_linux_menu_x11.py \
  --binary "$BUILD_ROOT/Debug/bin/KisakCOD-client-input" \
  --bundle "$PRIVATE_BUNDLE" --assets "$PRIVATE_IMAGES" \
  --menu-inventory "$PRIVATE_EXPORT/menu-inventory.json" \
  --composition "$PRIVATE_COMPOSITION_JSON" --output "$BUILD_ROOT/x11-menu"
```

ASSETS.md provides the exact single-export bundle, image and oracle preparation commands. PRIVATE_COMPOSITION_JSON is generated by the checked-in selector from actual menu/material inventories. That generated game-derived JSON stays private and is not included in this package. Do not replace it with guessed font metrics or arbitrary material metadata.
