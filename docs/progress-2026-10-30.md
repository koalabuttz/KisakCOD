## Native Linux client — next milestone

See [Native Linux client](linux-client.md).

`KISAK_BUILD_LINUX_CLIENT_CORE=ON` currently compiles:

- `src/client_mp/cl_net_chan_mp.cpp`
- `src/client_mp/cl_parse_mp.cpp`
- `src/client_mp/cl_input.cpp`

Only the command codec is executed by its runtime test. Parser/input coverage is
compile-only. `KISAK_OPENAL` selects portable header declarations for this target;
no audio implementation is compiled or verified. The D3D9 type declarations used
on Linux are not a renderer.

Recommended next work:

1. Check the hosted Debug/RelWithDebInfo workflow after pushing these commits.
2. Add bounded client parser/input runtime checks and extend client compilation
   one translation unit at a time, identifying unresolved platform dependencies.
3. Design native startup/window/event/input integration. Research renderer
   options against the existing D3D9 calls and asset/shader needs before choosing
   a backend; none has been selected tonight.
4. Plan sound and authentication integration explicitly. Do not equate a
   headless test harness or successful object build with a usable game client.

This is a substantial port. The useful foundation is now reproducible without
pretending the remaining platform/presentation work is already solved.

# Real client-core compilation and codec test; not a game executable.

    --build-type Debug --build-dir build-linux/client-core-final-debug

    --binary build-bots/bin/KisakCOD-dedi --bots 3 --timeout 45 --keep

checker deliberately refuses a cache that lost its opt-in. Build commands and
first-time prerequisites are in the linked guides.
